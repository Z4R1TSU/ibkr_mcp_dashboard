# IBKR MCP 持仓观察台

独立、单用户、只读的持仓看板。账户数据直接连接 IB 官方 MCP，不依赖 Codex 进程、Gateway 或 Flex。可选的 [thinkorswim 行情采集器](integrations/thinkorswim/README.md) 独立运行，不覆盖 IB 账户估值。没有交易接口，也没有内置账户或演示持仓。

## 这版能做什么

- 查看 IB 账户净值、现金、保证金、剩余流动性、持仓与未实现盈亏。
- 显示股票集中度、股票/期权盈亏贡献、空头期权到期日、行权资金需求与股票数量匹配。
- 独立采样 IB 行情，明确区分 REALTIME、DELAYED、FROZEN、FROZEN_DELAYED、无权限与未知状态。
- 净值观察按天展示，每天保留最后一次成功采集值，今日点随采集更新；不把净值变化冒充 TWR/MWR 或当日收益。
- 盈亏日历位于持仓下方、默认收起，点击左侧日历图标自动展开并跳转。按美东交易日展示盈亏，本地封板记录优先，其次为同账户本地日报，缺失日期由 IB 历史补充；可切换月份、金额 / 收益率并查看单日详情。高对比绿色盈利、红色亏损，附带方向符号和文字；金额完整显示、每周从周日开始，窄屏保持七列并自动缩小数字，无需横向滑动，“已获取交易日”显示已取得收益率的天数 / 当月截至美东今天应有的交易日数，不含休市和未来日期；每日格不重复显示盈利 / 亏损文字，缺失和暂估分开标注。金额仅在净值变动与 TWR 一致时展示，资金变动或跨日缺口不冒充单日盈亏，MTD 收益率计算月初至最新有数据日期的累计 TWR，并显示截止日；月初或中间缺失时不计算。
- 本机免密访问、公网密码保护、加密 OAuth 存储、CSRF 防护、错误退避、旧快照保留、浏览器自动接收更新。

**不是逐笔实时终端。** 默认每轮完成后等待 60 秒再拉取账户；每轮额外采样 4 个 USD 股票/股票期权，按最久未更新优先。16 个标的至少需要 4 轮，加上网络时间。可调整 `QUOTE_BATCH_SIZE`，但更多调用会延长轮次，不能承诺 IB 源数据同步刷新。

## 本地启动

需要 Node.js 24 或更高版本。已有安装应保留实际 `.env` 和私有 `DATA_DIR`，不要覆盖或公开它们。新安装默认使用被 Git 忽略的 `./data`。

全新安装：

```bash
npm ci
cp .env.example .env
npm run build
npm start
```

访问 `http://127.0.0.1:8048`，**直接进入看板，无需输入看板密码**。本地示例配置启用 `ACCESS_MODE=local`；会话过期或服务重启后自动恢复，不会要求重新输入密码。页面隐藏密码设置和退出登录入口，并标注「本机免密」。

`localhost:8048` 也可打开，首页会自动跳转到配置的标准本机地址，以保持 OAuth 回调和 Cookie 一致。没有 IB 授权时，仍需点「连接 IB」完成 `mcp.read` 授权；本机免密不等于绕过 IB 身份验证。

共享电脑需要密码保护时，可设 `ACCESS_MODE=password`，重启服务后在同目录运行 `npm run show-login` 查看初始密码。没有配置 `ACCESS_MODE` 时也保持密码模式。公网 Compose 配置明确固定为密码模式。

已有运行环境：`npm run build && npm start`。`npm run dev` 会先构建前端再监视后端；改动前端后需重新构建，不提供 Vite 热更新。

## 授权如何工作

1. 服务预加载 IB OAuth 公开配置；首次连接、回调地址变化或客户端失效时动态注册独立客户端，后续复用有效客户端。
2. 浏览器跳转 IB 官方授权页，只请求 `mcp.read`。
3. 回调绑定当前看板会话（本机自动建立，公网经密码登录建立），并检查 state、PKCE。
4. access token、refresh token、客户端元数据保存在 AES-256-GCM 加密文件中。
5. 后台统一管理令牌续期；撤权、失效、地区不可用等情况仍可能需要人工重新授权。**没有保证永久免登录。**

服务使用 IB MCP 的 401 WWW-Authenticate 响应指定的资源元数据地址（MCP 地址下的 /.well-known/oauth-protected-resource），不依赖 SDK 猜测路径。授权、令牌交换和刷新均携带元数据声明的 resource；发现失败时停止授权，避免生成缺失资源标识的链接。

公开授权配置缓存 1 小时，临时服务错误不会缓存；预加载只发公开 GET 请求，不创建授权、不修改令牌。点击连接仍生成新的 state 和 PKCE。OAuth 网络准备及交换阶段设有 20 秒截止时间，页面显示准备中或超时提示；日志分别记录采集等待、授权准备及接口耗时。动态注册响应列出的客户端可用权限可能更广，但每次授权仍只请求 mcp.read，并拒绝保存更广权限的令牌。

到期前主动续期与 MCP 请求收到 401 后的续期共用一个入口，均独立于浏览器登录；总截止时间 60 秒、单个请求最多 45 秒（已发出的令牌交换除外，见下文）。并发续期共用一次请求，成功后保存轮换的刷新令牌；迟到的旧令牌 401 直接复用新令牌，取消单个读取不会取消正在进行的续期。401 续期成功后仅重试原请求一次；再次 401 保留凭据并交由采集器退避，403 不扩大权限。SDK 不再自行启动后台授权流程。

临时故障保留授权，由采集器退避重试。只有 IB 明确返回 invalid_grant、invalid_client 或 unauthorized_client 时才清除对应凭据。ibkr_token_refresh 日志区分 expiry/http_401 触发来源，记录标准错误码及是否需要重新授权；ibkr_mcp_auth 记录 401/403 与重试是否被拒绝，不输出凭据或接口错误描述。

美东交易日 04:00–20:00（含盘前盘后）以外、周末及休市日为非活跃时段。IB access token 约 10 分钟有效，每次超过 10 分钟后的读取都要轮换一次刷新令牌；非活跃时段的账户采集、PA 业绩、日线与成交缓存改为按 `CLOSED_POLL_SECONDS`（默认 6 小时，按 UTC 整点对齐）共用同一读取时刻，下一交易时段开始时立即恢复每分钟采集。期间快照在下一次计划读取前不标记为过期，看板显示“休市低频采集 · 下次 时:分”。手动刷新、/刷新 与读取失败后的 30/60/120 秒重试不受影响。工作日的令牌轮换由约 144 次降到约 99 次，周末由约 290 次降到约 10 次。

已多次观察到 IB 轮换响应丢失后，旧刷新令牌被 `invalid_grant` 拒绝。令牌交换发出后单独限时 5 分钟收完整个响应，不受读取方取消影响。每次交换使用全新连接，结束后关闭，不与数据读取共用连接池。停服等待续期保存；systemd 停服期限为 360 秒，健康检查和安装器也预留相应时间。

`ibkr_token_exchange` 只记录出口类型、响应头耗时、已收字节数及阶段。响应体丢失为 `status=200, phase=body`；没有响应头为 `status=null, phase=headers`，同样不能假定 IB 未消费令牌。除确定的建连前失败外，网络层不立即重放、不切换出口；上层退避重试若收到 `invalid_grant`，仍需重新授权。连接隔离不能保证外部链路永不丢包。10/28 两次故障的证据和处理见 [排查记录](docs/ibkr-auth-2026-10-29.md)。

IB 完成授权并访问回调后，浏览器会自动返回看板，显示授权结果并启动采集。会话失效、授权取消、state 不匹配或令牌交换失败也会返回看板并显示对应提示；没有有效会话时不会交换授权码。会话 Cookie 按 PUBLIC_URL 的 origin 隔离，避免本地看板与 SSH 转发看板在同一浏览器中互相覆盖。服务日志中的 ibkr_authorization 只记录流程阶段与时间，不记录授权链接、code、state 或令牌。若浏览器仍停留在 IB 的 SSO 页面，表示它尚未返回看板回调，不能据此认定授权完成。

当前机器已用现有只读授权验证过真实读取；服务器的独立 OAuth 回调需要在实际 HTTPS 域名上完成一次联调。不要复制本机令牌到仓库，也不要让多个服务共用、竞争轮换同一个 refresh token。开发环境可以显式使用 `npm run import-codex -- '<已核实的钥匙串条目>'` 导入，但不推荐把该方式作为服务器长期方案。

MCP 固定地址：`https://api.ibkr.com/v1/api/mcp-public`。允许的工具在 `server/ibkr.ts` 中列明；前端无法指定任意 MCP 工具，也没有下单路由。

账户采集使用优先队列，持仓、摘要、余额连续读取；整组包含排队最多等待 120 秒，普通读取最多 90 秒。独立行情在账户快照发布后采样，每轮总预算 20 秒。超时取消等待中的任务并关闭相应连接，避免旧任务继续占用队列。账户读取失败按 30 秒、60 秒、最多 120 秒重试；成功后恢复配置的轮询间隔。页面区分排队、连接、读取账户、更新行情和等待重试，展示上次成功时间与下次尝试倒计时。

IB 使用独立连接池，连接期限 30 秒、单次 HTTP 请求总期限 45 秒。 可用 `IBKR_HTTP_PROXY` 为 IB MCP 与授权请求单独配置 HTTP CONNECT 代理，留空直连；始终校验 IB 官方域名和 TLS 证书。连接层只对尚未建立连接的暂时性失败重试一次；响应丢失、HTTP 错误和已取消请求不由连接层自动重放。MCP 明确返回 401 时按上述规则续期并重试一次。续期时的临时网络失败保留尚未过期的授权发现缓存。日志记录工具名、排队时间和请求耗时，不记录令牌、参数或账户金额。

令牌交换还可单独配置 `IBKR_TOKEN_HTTP_PROXY`：未设置时沿用 `IBKR_HTTP_PROXY`，显式留空使用直连，填 HTTP(S) 代理则使用该出口。先用不带凭据的 IB 公开元数据请求验证线路，确认后在下一次交换前切换；不要用真实刷新令牌同时测试多个出口。

## 服务器部署

Linux 可使用下文的 systemd 安装器部署。服务器常驻运行后，飞书机器人处理消息不再依赖 Mac 是否开机或休眠；上传 GitHub 本身不提供运行服务。保持只读边界，不启用任何下单能力。

### 完整持仓助手：飞书 + TradingAgents

当前完整助手的迁移路径是 Linux 上的 Node.js 24+、Python 3.12+ 和 [lark-cli](https://github.com/larksuite/cli)。现有 Docker 镜像只包含看板，**没有 lark-cli、Python 研究环境或完整助手的环境变量配置**，不能仅运行下文 Compose 命令就获得飞书研究能力。

```bash
git clone https://github.com/Z4R1TSU/ibkr_mcp_dashboard.git
cd ibkr_mcp_dashboard
npm ci
cp .env.example .env
```

迁移前逐项完成：

1. 在服务器私下配置 `.env`，保持权限 0600；公网看板使用 `ACCESS_MODE=password`、可信 HTTPS 的 `PUBLIC_URL` 和私有持久化 `DATA_DIR`。用 HTTPS 反向代理连接仅监听本机的应用端口，不把默认的本机免密模式暴露到公网。
2. 在运行服务的专用系统用户下安装并配置 lark-cli，连接**已有的持仓助手应用**，使用同名或新的独立 profile，并设置 `FEISHU_ENABLED=true`、`FEISHU_PROFILE`、`FEISHU_CLI_PATH` 和对应应用的 `FEISHU_BOT_OPEN_ID`。不要为了迁移新建另一只机器人。已注册的 `/research` 属于飞书应用，无需随服务器重建。
3. 单独配置原有 `MODEL_PROVIDER / MODEL_BASE_URL / MODEL_API_KEY / MODEL_NAME`，确认服务器可以访问该模型网关。尤其是 AIDP 模式，不能仅凭 Mac 上可用就认定服务器网络和授权也可用；不要擅自更换模型。
4. 安装 Python 3.12+ 后运行 `npm run research:setup`，再运行 `npm run build`。用运行服务的同一系统用户安装研究环境，确保研究子进程能够访问它。
5. 在服务器重新完成 IB 的独立只读授权，并在管理员私聊重新绑定助手。IB 令牌、模型密钥、飞书 CLI 配置、持仓缓存、研究报告和聊天记忆均不通过 Git 迁移；不要复制整份状态让两台机器争用同一 refresh token。
6. 切换时先停止 Mac 上的旧实例，再让服务器实例接收同一机器人的消息。单个账户只运行一个服务进程，不共享状态目录、不启用多副本。用服务器的进程管理器保持 `npm start` 常驻并开机启动，Linux 也可使用 `npm run service:install` 配置 systemd。
7. 先验证看板、飞书连接及 `/research help`，再手动验证一次研究；只有客户端收到帮助和研究报告，才算完整迁移完成。Discord Rich Presence 依赖本机 Discord 客户端，不会因上传代码而变成服务器端能力。

### 仅看板：Docker Compose

以下配置仅部署看板。需要 Docker Compose 及指向服务器的域名；只公开 HTTPS 反向代理，不公开应用的 8048 端口。

1. 仅上传本项目源代码与锁文件；排除 `.env`、`data/`、`node_modules/`、`dist/`，不上传工作区的私有状态。
2. 安装 Docker 与 Compose，配置 DNS，开放入站 80/443；SSH 仅对管理来源开放。
3. 创建服务配置并修改域名：

```bash
cp .env.server.example .env.server
docker compose --env-file .env.server up -d --build
docker compose --env-file .env.server exec app npm run show-login
```

4. 在浏览器访问配置的 HTTPS 域名，使用初始看板密码登录，立即改密码，再完成 IB 只读授权。
5. 检查页面的数据源时间、行情源状态，以及故障后的过期标识。浏览器关闭不影响服务器采集。

`PUBLIC_URL` 由域名自动生成，也是 OAuth 回调的基址。修改域名后需重新授权。若坚持直接使用公网 IP，需要为该 IP 配置浏览器信任的 TLS 证书，并对应修改代理与 `PUBLIC_URL`；不要把 HTTPS 换成明文 HTTP。也可先用 SSH 隧道私下验收，而不是提前暴露持仓页面。

部署配置已提供，但本机没有 Docker，**未执行镜像构建、公网 TLS 或服务器 OAuth 回调验证**。Caddy 默认配置不启用请求访问日志，避免记录授权回调查询参数；若以后启用日志，务必脱敏 `/auth/ibkr/callback`。

## 数据与金融口径

| 项目 | 口径 |
| --- | --- |
| 账户净值、现金、保证金 | 直接使用 IB 账户摘要；不以独立行情重估净值 |
| 持仓未实现盈亏 | 直接使用 IB 持仓接口；不是今日盈亏 |
| 账户未实现盈亏 | 使用 BASE 汇总行；不再加一次 USD 等币种行 |
| 集中度 | 正市值股票 / 账户净值；前三项同口径 |
| 构成图 | 各类持仓绝对市值 / 全部持仓绝对市值；不含现金，不是 Delta 敞口 |
| 期权识别 | 从 IB 描述的合约代码解析到期日、类型、执行价和明确的乘数；原始 asset_class 保留 |
| 整体 Delta 杠杆 | 同标的股票股数 + Σ(带符号期权张数 × 乘数 × Delta)，乘正股现价；各标的净敞口取绝对值相加 / 最新 IB 净值。备兑 Call 抵消同标的股票，跨标的多空不抵消；数据暂缺时展示带原始时间的上次完整快照；持仓变化后不复用旧杠杆 |
| 风险更新时间 | 活跃时段随账户采集更新，默认 60 秒；休市默认 6 小时并保留标明时间的历史参考。SSE 保活不重算；净值不以行情重估 |
| 卖 Put 金额 | 执行价 × 空头张数 × 乘数；未抵扣权利金、未考虑保护性组合，不是亏损或保证金 |
| Call 股票匹配 | 同标的同币种持股数量依到期日分配，避免重复覆盖；不代表券商认定的备兑 |
| 缺失值 | 保留 null，显示为 —；不填零、不生成假行情 |
| 多币种 | 保留原币种；没有验证 FX 口径前，跨币种合计暂停 |
| 报价 | USD 股票及可匹配的标准股票期权优先嘉信，缺失或过期时回退 IB；逐项标注来源 |
| 行情时间 | fetchedAt 为接收或确认时间；lastTradeAt 仅保留供应商明确提供的成交时间，不用心跳伪造成交时间 |

账户摘要、持仓、余额是分次调用，不是原子快照；差额独立显示，不为凑平强行归因。调整期权的交割资产需要另核实；本版提供已核验 Greeks 的 Delta 敞口，不提供压力测试、分红现金流或税务计算。

## 安全和运行边界

- 本机免密模式只能绑定回环地址，要求本机 HTTP URL 与监听端口一致；公网地址、通配监听和端口不匹配会拒绝启动。
- 本机模式检查连接来源、Host、Origin、浏览器请求来源和代理转发头，拒绝外部站点及代理请求。本机用户或进程可以直接读取数据，不能用此模式保护共享电脑上的账户隐私。
- 不要通过隧道、改写 Host 或剥离转发头把免密端口公开；公网部署必须使用 `ACCESS_MODE=password`。部署环境继续使用 Secure、HttpOnly、SameSite Cookie。
- 本机账户读取与 SSE 自动建立会话；刷新及 IB 授权等 POST 仍需来源检查和 CSRF。密码模式保留登录限速及修改密码后的全会话撤销。
- 内部会话默认 8 小时：本机过期/重启会自动恢复，无密码操作；密码模式过期/重启仍需登录。这与 IB OAuth 独立，不改变或延长 IB 的授权有效期。
- 状态目录权限 0700，文件 0600。OAuth 文件加密，但密钥也在该目录；**不能抵御服务器/整目录被攻破**，需保护系统、磁盘和备份。
- 持仓缓存是私有明文 JSON，便于可靠恢复，不能作为静态文件发布。高频缓存默认保留至多 1,440 个采集净值点且不超过 7 天；每日记录另存 `dailyHistory`，最多保留 180 个有数据的日期，网页“净值观察”合并两者后按日展示。日期固定按美东时间 `America/New_York` 归并，自动处理夏令时，不跟随通知时区，横轴显示日期并保留缺失日期的间隔；每天取最后一次成功快照，今日持续更新，不代表交易日收盘净值，缺失日期不补值。
- 收到失败不清空持仓，显示旧数据及错误；账户或报价失效不会被包装成“实时”。
- 当前只支持一个服务进程、一个账户授权、一个管理员，不要水平扩容共享状态目录。
- 飞书支持专用机器人私聊、日报和状态提醒；可选 thinkorswim 模块提供只读行情，自动交易不在范围内。

## 飞书持仓助手

通过独立的 lark-cli profile 接收飞书长连接事件，凭据由 CLI 管理，不复制到应用源码。
运行环境需同时安装 Node.js 24+ 和 [lark-cli](https://github.com/larksuite/cli)。
本机已创建专用 profile：ibkr-portfolio，对应应用“持仓助手”。

1. 新环境运行 lark-cli config init --new --name ibkr-portfolio，按官方页面完成应用创建。
2. 配置 FEISHU_ENABLED=true、FEISHU_PROFILE=ibkr-portfolio。非交互启动时可把 FEISHU_CLI_PATH 设为可执行文件绝对路径。
3. 应用需要发送消息、接收私聊权限，并订阅 im.message.receive_v1。收件表情需要 im:message.reactions:write_only（或已具备覆盖该接口的 im:message 权限）。创建流程通常已配置；连接失败时检查飞书后台。
4. 启动服务，打开看板左下角“飞书与模型”。将显示的 15 分钟一次性绑定指令私聊发送给机器人。
5. 私聊仅处理绑定用户的消息；群聊按看板中的群和成员权限处理，必须真实 @ 机器人。机器人消息与过期事件会忽略。

时区由 FEISHU_TIMEZONE 配置，默认 Asia/Shanghai。日报每 30 秒检查一次，仅在本轮有新完成的美股交易日时推送，按报告交易日去重；北京时间 11:00 的订阅通常在周二至周六发送，周日、周一及美股休市后的早晨跳过。停机或数据延迟时仅在原定时间后一小时内补发目标交易日的报告，不以旧日报替代；每天、每个交易日均最多自动推送一次。状态不变时不重复提醒。消息 ID 和推送记录持久化，发送使用幂等键。

IBKR / 嘉信登录失效提醒在飞书启用并绑定管理员后自动开启，不受“关闭提醒”或 /alerts off 影响。服务启动时检查，此后每 30 秒独立检查本地认证状态，不受日报或模型问答阻塞，也不额外请求券商接口。需要重新登录时，向管理员私聊发送券商名称、发现时间和登录入口。正常续期、网络超时、嘉信重连和缓存异常不会触发登录失效通知。休市期间沿用券商原有采集计划，只有实际检测到认证失效后才提醒，不能预知服务端尚未返回的失效。

每个券商每次失效只提醒一次；发送失败自动重试，记录持久化，重启或跨日期不重复。确认登录恢复后再次失效才重新提醒，不另发登录恢复消息。数据过期／恢复提醒仍可单独开启，授权失效期间抑制重复的数据通知。“飞书与模型”展示登录检查时间、各券商状态和发送错误；未启用嘉信集成时跳过嘉信提醒。

普通回复与日报使用飞书富文本（post），渲染 Markdown 的标题、加粗、列表和代码块。长回答优先按段落或换行分段，代码块跨消息时重新封闭。飞书富文本并非完整的网页 Markdown 渲染器。

通过权限、时效和去重检查的消息会立即收到“收到”（Get）表情，包括正在排队的消息。表情仅表示已接收；最终结果仍以回复为准。无权限消息、重复事件、未绑定时的无效指令不加表情。表情接口最多等待 5 秒，失败不阻止回答，原因显示在看板“飞书与模型”。

看板卡片可在手机和电脑的飞书聊天内查看，不需要公开本机服务。卡片展示发送时的快照，不自动更新；再次发送“看板”查看最新缓存，发送“刷新”重新采集。净值轨迹与网页统一按美东时间 America/New_York 每天保留最后一次成功采集的净值，自动处理夏令时，最多展示最近 60 个有数据的日期；今日点随采集更新，不代表收盘净值或收益率，缺失日期不补值。纵轴围绕所示净值的最低值、最高值自动留白，不强制从零开始；卡片说明缩放口径。每日记录独立保存在 dashboard.json 的 dailyHistory 中，最多保留 180 个日期，首次启动从已有高频记录归并，避免被高频缓存淘汰；旧的北京时间日记录按原始采样时间重新归入美东日期，已淘汰的采样无法恢复，因此旧日期仅保留现有记录中的最后值；持仓分布逐一展示所有正股标的与账户现金，以正股市值加现金计算占比，排除期权与其他资产；右侧图例列出标的名称和比例，图表高度随标的数量增加。空头和负现金使用绝对金额并标明空头/借款。仅正股跨币种、缺失市值或现金未知时不画分布，已排除的期权不会阻止绘图。分布环图显式设置内外半径，避免默认外半径与内半径重合而不可见。快照时间、过期状态和本机网页访问限制会在卡片中说明。卡片发送失败时回退到账户摘要；群聊沿用原有权限与 @ 校验。Card 2.0 需要飞书客户端 7.20 或更高版本。

本机免密地址仅能在同一台电脑打开；手机接收消息不受影响。首次/失效的 IB 授权仍需在服务所在电脑的看板完成。服务器部署时改用可信 HTTPS 域名。

现有 Dockerfile 只打包看板，未包含 lark-cli。部署机器人时先使用安装了 lark-cli 的 Node 运行环境，并单独完成服务器端的飞书 profile 与 IB 授权配置；不要直接复制本机钥匙串。

### 日报内容与保存

日报还包括 CNN 恐慌与贪婪指数（0–100 和情绪标签）、纳斯达克100 PE（TTM）、Forward PE（未来12个月），以及两项估值各自的近10年分位数。CNN 指数读取 FearGreedMeter 公开网页中的 CNN 转载序列；估值直接读取 [Trendonify PE 页面](https://trendonify.com/united-states/stock-market/nasdaq-100/pe-ratio)和 [Forward PE 页面](https://trendonify.com/united-states/stock-market/nasdaq-100/forward-pe-ratio)，分位数取各自历史比较表的“10 Year”行。每项注明数据日期；日期晚于报告日或早于报告日超过7天时不使用。网页暂时不可用时可沿用日期合格的缓存并标注；缺项不影响账户日报。

日报仅私聊发送给绑定的账户管理员，不发到群。使用最近一场已完成的美股常规交易日：例如北京时间周二上午回顾周一美股，交易日按纽约时区及实际返回的交易日日线选择，不用北京时间自然日截断。日报包括相邻交易日账户净值差、官方 TWR 单日收益率、大盘 ETF 和当前持仓股票前五的价格表现、行情复盘。

金额按“净值变动口径”展示，同时用 TWR 检查明显不一致；出现差异时提示可能有入出金或其他调整，不把入金当成交易盈利。大盘用 SPY、QQQ、DIA、IWM 代表不同指数风格，大盘和持仓均只展示收盘价较前收的涨跌幅，行情复盘使用相同口径。账户和价格涨跌数据来自 IB MCP，不编写未经证实的新闻原因。

复盘模型会同时取得看板的完整账户快照，包括全部持仓、数量、市值、净值权重、现金、期权及已有风险指标，使用现有缓存，不额外采集账户。正文只提与结论相关的持仓，不逐项重复清单；前五只股票的行情表不代表模型只知道这五个持仓。当前快照保留采集时间和过期状态，与报告交易日的净值和收益分开使用；日线缺失不等于持仓未知，当前仓位也不能替代昨日交易及逐仓盈亏数据。

发送“日报”或“推送一次”可在私聊查看。看板“飞书与模型”提供预览；每个交易日的报告及计算数据保存到私有 DATA_DIR/daily-reports，文件权限 0600。完整账户背景仅随 JSON 保存，TXT 和消息不追加完整持仓表。同样的数据会复用报告；背景变化或报告版本更新后可重生成复盘，但已封板的账户盈亏与 Discord 共用同一份固定记录。

### 群聊访问设置

日报估值采集使用独立的 Chromium 配置目录 `DATA_DIR/daily-market-browser`；先封板账户收益，再抓取公开网页。指标缓存保存在 `DATA_DIR/daily-market-indicators.json`（0600），15分钟内复用。新机器需安装 Chromium（`npx playwright-core install chromium`），Linux 还需 Xvfb 和浏览器动态库；当前服务器复用已有安装，可通过 `DAILY_CHROMIUM_PATH`、`DAILY_XVFB_PATH`、`DAILY_BROWSER_LIBRARY_PATH` 指定路径。网页采集子进程不接收 IB 或模型凭据。

以后启用新群：先在飞书群里添加“持仓助手”，再打开看板左下角“飞书与模型”，点击“刷新已加入的群”，选择权限后保存。无需重启服务。

每个群可设置“关闭群聊”“仅我可用”“全群成员可用”“指定成员可用”。指定成员可按姓名勾选，也可填写 open_id；账户管理员在已开启的群中始终可查询。成员列表需要 im:chat.members:read 权限；群 @ 事件需要 im:message.group_at_msg:readonly 权限。FEISHU_BOT_OPEN_ID 应填写这个应用的机器人 open_id，用于核验真实 @。

群聊只提供查询，订阅、偏好、绑定和 IB 授权仅在管理员私聊中管理。群内问答不附带管理员的私聊偏好。群配置保存在私有 feishu-bot.json；管理接口沿用看板会话和 CSRF 校验。

### 换汇与入金口径

询问平均换汇成本、与当前汇率相比赚亏多少时，程序先计算本年 CNH 买入 USD 的加权成本，再通过 USD.CNH 合约的 CASH/IDEALPRO 报价取得买卖中间价。合约必须唯一匹配，CFD 不参与；报价缓存 30 秒，仅使用标记为 REALTIME 或 DELAYED 的有效买卖价。报价缺失、冻结或状态未知时明确不计算当前百分比。

以 CNH 计价的纯汇率变化率为（当前 CNH/USD 汇率 ÷ 历史买入加权成本 − 1）×100%。这是本年买入价格的比较，不等于扣除所有反向换汇后的剩余美元成本，也不等于当前账户全部美元资产或账户总收益。结果不包含投资收益、利息和未确认的费用。程序计算结果会提供给模型解释；模型失败时仍返回这些已核实结果。

“今年换汇”读取 get_account_trades 的 YEAR_TO_DATE 响应，按交易 ID 去重并按时间列出全部返回的 CASH 记录，缓存 5 分钟。时间显示为北京时间，查询年度边界按 IB 的 UTC 口径。CNH↔USD 分开汇总买入、卖出及相抵净额，不能当成入金总额；手续费币种未提供时不猜测或扣减。当前 MCP 没有入出金流水，累计入金本金仍需 IB 账单核对。自由问答提及换汇/入金/出金/汇率时会补充这些历史数据。

网页新增“入金记录”：按美元换汇间接推算入金、出金参考。换入 USD 记为入金参考，换出 USD 记为出金参考，同时支持 USD.CNH、CNH.USD 等美元货币对；显示原币金额、换汇方向、汇率和原始手续费。净额为换入减换出，按成交 ID 去重，保留同日双向换汇及不足一分钱的余额转换；未明确手续费币种时不扣减。非美元货币对及缺少有效金额、币种或方向的记录不参与推算并提示数量。

入金记录与盈亏日历一样默认收起，点击标题展开或从侧边栏快捷跳转；收起时停止加载和轮询。平均换汇汇率按“原币金额合计 ÷ 美元金额合计”加权，换入、换出美元分别计算，CNH、HKD 等币种分开展示；没有对应方向的换汇时显示“—”，不计币种未确认的手续费。

入金记录复用“今年”成交查询及私有 `trades.json` 缓存，并保留已保存的往年年度查询；不会把近 60 天缓存当成全年。支持方向筛选、分页和手动刷新，查询失败保留旧记录并标注状态。换汇均价与金额汇总使用整个已展示日期范围，不随明细方向筛选或分页变化。换汇推算不是实际银行入出金或经核对的累计本金，不自动修改 Discord 净成本。

盈亏日历按美东换汇发生日附加入金、出金标记和逐笔详情，含休市日及缺少业绩的日期；有记录的月份额外显示换入、换出和相抵净额。换汇推算独立于盈亏，不扣减净值差、不改变 TWR、月度盈亏及交易日计数；没有换汇的日期和月份保持原有展示。日期小格使用简写，点选可查看精确金额。首次换汇早于业绩历史时，也可选择该月份。

网页“交易记录”提供左侧快捷跳转，默认展示上一美股交易日，跳过周末和已知美股休市日；可快速选择今天、近 7 天、近 30 天、本月和今年。所有范围边界、日期分组和成交时间都使用 `America/New_York`，标注 EDT/EST，自动处理夏令时。支持标的及 Put/Call 搜索、分页和手动刷新。

近期范围读取 `DAYS_60` 后按美东日期筛选；今年使用独立的 `YEAR_TO_DATE` 查询和年度缓存，不把近期数据冒充全年。UTC 已跨年但美东仍在旧年时，会合并前四个季度和 UTC 本年数据，再按美东年度裁剪。各范围返回明确的起止日期；切换范围时不会把旧范围结果放到新标题下。

交易类型显示为“买入正股”“卖出 Put”“买入 Call”等。优先使用成交自身的合约字段；否则通过只读 `get_account_orders(show_completed=true)`，按订单 ID、标的和方向精确关联合约描述并缓存。该接口只保证当前订单及当日完成订单，无法补齐全部历史期权。缺失类型明确显示 Put/Call 未提供，不按买卖方向、公司名或当前持仓猜测。

用户明确确认的单笔类型可保存在私有 `DATA_DIR/trade-annotations.json`，同时校验成交 ID、标的、方向和原始时间；界面标为“你已确认”，不冒充 IB 字段，也不改券商记录。此次 APP 的 2026-10-13 成交 Put 标注来自用户此前的明确确认。

成交独立加载，成功记录按近期/年度分别缓存 5 分钟，保存到私有 `DATA_DIR/trades.json`（0600，旧版缓存只迁移为近期数据）。查询失败保留该范围上次成功记录和时间；没有完整年度数据时不会显示为“全年无成交”。手动刷新至少间隔 30 秒，页面打开期间会自动重试与更新。

近期成交能力核对（2026-10-14）：已从 IB 官方 MCP 的 `tools/list` 取得 `get_account_trades` 定义，标记为只读、幂等。唯一参数为 `period`，默认 `TODAY`；支持 `DAYS_7`、`DAYS_30`、`DAYS_60`、`DAYS_90`、`MONTH_TO_DATE`、`YEAR_TO_DATE`，以及 `LAST_QUARTER`、`TWO_QUARTERS_AGO`、`THREE_QUARTERS_AGO`、`FOUR_QUARTERS_AGO` 四个已完成季度。

所有查询边界均为 UTC，不能将 `TODAY` 直接当作美东当天。按美东日期显示或筛选时，应读取覆盖完整区间的窗口，再按 `America/New_York` 转换成交时间。可直接查询 `DAYS_7` 等窗口，无需从本年数据裁剪，避免跨年漏查。

输出 schema 包括成交 ID、时间、标的、证券类型、买卖方向、数量、价格、币种、手续费、净额、已实现盈亏、订单 ID、订单类型和交易所等字段；未声明必填，缺失时保留未知。现有换汇模块的 `CASH` 筛选发生在应用端，网页已接入“近期交易”栏。接口未公开分页或条数参数，也未说明更新延迟和单次返回上限，不能据此承诺完整历史或实时推送。

实测 `get_account_trades({ period: 'DAYS_7' })` 于 2026-10-14 07:25 UTC 返回 7 笔、7 个唯一成交 ID，覆盖股票和期权；最新成交为 2026-10-13 13:56:44 美东时间。此前连接曾间歇性超时，过期访问令牌也返回过 401；服务成功续期后，工具定义和成交查询均已成功。该单次结果不代表网络问题已根治。


### 模型接入配置

MODEL_PROVIDER 默认为 chat-completions。本机目前使用 aidp，模型为 gpt-5.6-sol。
在 aidp 模式下，MODEL_BASE_URL 填完整地址 https://aidp.bytedance.net/api/modelhub/online/v2/crawl（不含查询参数），MODEL_API_KEY 单独保存密钥。
请求时自动将密钥编码为 ak 参数，生成 X-TT-LOGID，并按 AIDP 格式发送文本数组；不追加 /chat/completions，也不发送 Bearer 认证或 store 字段。
MODEL_MAX_TOKENS 控制 AIDP 推理与回答的合计额度，当前设为 32768。示例中的 500 对分析问题可能全部耗在推理上而没有正文；遇到额度耗尽、空回答或格式错误会分别记录原因，并返回已核实的数据，不把推理内容当答案。
可运行 node --import tsx scripts/probe-model.ts 测试简单问答，或添加 --portfolio-fixture 使用虚构账户验证完整流程。测试不发送真实持仓或飞书消息，也不打印密钥。

为 TradingAgents 接入验证模型协议，可运行 `node --import tsx scripts/probe-trading-model.ts`。它复用当前 MODEL 配置，最多发送 3 次模型请求，检查原生工具调用、工具结果回传和 JSON Schema 输出；会消耗模型额度，但只发送虚构测试数据，不访问 IB 账户、不发送飞书消息、不启动研究任务。协议测试通过不等于 TradingAgents 已完成接入。

以下说明适用于默认的 chat-completions 模式：

在本机 .env 中填写 MODEL_BASE_URL、MODEL_API_KEY、MODEL_NAME，重启服务即可启用。BASE_URL 是包含 /v1 等路径的 API 基址，程序追加 /chat/completions。例如供应商给出的完整地址是 https://your-provider.example/v1/chat/completions，则填写 https://your-provider.example/v1。

采用 [Chat Completions 请求/响应格式](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)，使用 model、messages、stream=false、store=false，读取 choices[0].message.content。供应商需兼容这些字段。MODEL_TIMEOUT_SECONDS 默认 300 秒。远程接口要求 HTTPS；允许回环 HTTP 连接本地模型，若本地模型忽略 API Key，可填任意非空占位值。

未配置模型时，自由问答提示待配置；账户命令和主动推送照常可用。配置模型后，自由问答和日报复盘会向指定接口发送所需账户事实，不发送 IB 令牌或飞书凭据。模型不执行交易。MEMORY_ENABLED=true 时，历史保留量由 MEMORY_MAX_TURNS 和 MEMORY_MAX_CHARS 控制（默认 20 轮、200000 字符）。MODEL_CONTEXT_TOKENS 单独控制每次请求的输入预算，默认 100000 token；超限时仅移除最早的完整历史轮次，保留系统说明和当前问题。token 数按 o200k_base 估算，响应中的 promptTokens 是模型服务报告的实际用量。私聊与各群分别保存，群内不带私聊偏好。聊天记录在本机加密保存，可用“清空上下文”清除当前会话。群聊清空仅限账户管理员。

绑定与推送设置保存在私有 DATA_DIR/feishu-bot.json（0600），一次性绑定指令在未绑定期间保存在 feishu-pairing.txt（0600）。不要把私有状态目录公开或加入仓库。

### 只读约束与运行配置

**绝不下单。** 只调用公开研究数据工具，工具名称使用白名单；研究子进程不接收 IB、飞书或真实模型密钥，也没有订单、撤单、转账、Shell 或 MCP 工具。TradingAgents 的 Trader / Portfolio Manager 节点只生成研究文本；报告中的 Buy / Sell、价格和仓位都是研究方案，不会执行。既有 IB 只读接口没有变动。

研究使用固定版本的 Python TradingAgents 工作流及本项目的数据核验适配层。基本面章节直接输出带披露日期、期间、单位和来源的财报及程序计算指标；技术面、新闻、情绪、多空和风险讨论所需的模型均绑定到同一组 MODEL 配置。AIDP 继续使用本机认证桥接及 Chat Completions。

研究评级从强看多到强看空统一为 `strong buy`、`buy`、`hold`、`sell`、`strong sell`。研究经理和组合经理的模型输出格式、摘要、完整报告及保存的评级字段使用同一套五档；强弱两档在文本回退时也保留。关键资料不足时暂不评级，无法识别的结论标记待复核。

研究启动时复制账户事实、风险指标、分币种余额和报价时间，不刷新或修改账户；没有快照仍可研究公开标的。未知数量或金额不变为零，期权保留合约字段，过期快照在报告中注明。研究日与新闻窗口统一为纽约日期；不是历史回测。保证金缓冲率使用剩余流动性除以贷款权益，不能用净值替代分母。

研究另行主动读取标的最新美股报价，优先嘉信，失败后使用现有 IB 只读客户端；没有持仓也会按代码查询。最新成交、mark、买卖价与常规收盘分开保存，不用持仓成本或前收盘替代最新价。报告价格固定于任务启动时，摘要和正文展示来源、接收时间、交易时段及延迟状态；来源未提供成交时间时明确标为未知。日线用于历史指标，按交易日历、提前收盘及 15 分钟结算缓冲核验截止日。模型使用结构化价格引用，价格差幅和相对技术位由程序计算。比较必须绑定明确左右对象，定性文字无法自动判断时不取消整份评级；技术及新闻章节在多空讨论前最多局部改写一次，仍无法核验的内容由程序事实摘要替代。核心报价缺失或最终仍有明确价格错误时暂不评级。前收盘与后续报价的大幅变动本身不视作数据错误。

每次研究保存私有的 market-context.json、price-facts.json 和 price-validation.json（进入模型阶段后），用于追溯价格输入、计算和报告校验。运行 `node --import tsx scripts/check-research-quote.ts GOOG` 可只读核验嘉信即时查询，不读取账户、不调用模型、不发送飞书消息。行情服务更新后需重启 thinkorswim-market，Node 更新后需构建并重启看板服务。

研究独立于普通聊天队列，每次只执行一个任务，不定时运行、不自动重跑。群聊沿用现有 @ 与成员权限，结果返回原聊天前再次检查权限；私聊与各群的报告和研究记忆相互隔离。默认总时限 1800 秒、模型请求上限 100 次；每次模型调用仍使用现有超时和 token 上限。模型请求串行发送；遇到 HTTP 429 最多等待重试 3 次，遵循不超过 120 秒的 Retry-After，否则使用 15/30/60 秒退避；过长的 Retry-After 直接报告限流，不提前重试。重试也计入总请求预算，取消会中止等待。达到限制会明确失败或停止，不把部分输出当完整报告。服务重启后不恢复未完成任务，以免重复消耗模型额度。

首次安装（本机服务，Python 3.12+）：

研究先核验行情、SEC 已披露财报和新闻。关键数据不可用时，保存可用资料并标记“资料不足（部分研究）”，暂不评级，也不启动多轮模型讨论。非 SEC 覆盖标的目前会因缺少可核验财报而降级。其他来源缺失会列在数据覆盖表中；无有效情绪样本时分数为空。指标历史不足、缺失 OHLCV 不会被填成有效指标。

最新披露检查使用 SEC submissions，并读取最近业绩申报的 8-K 附件。业绩公告和正式财报的期间分开显示；已有新公告但读取失败时暂停评级。核心收入、净利润、经营现金流必须覆盖同一正式报告期间；超过 200 天仍无更新财务期间时不用于当前评级。Form 4 读取最近 30 天内最多 10 份申报，按交易日、披露日、证券类别和交易代码展示；赠与、行权、扣税不当作公开市场买卖，超出上限明确标注部分覆盖。

新闻优先使用官方公告，具备 Alpha Vantage NEWS_SENTIMENT 接口权限时可补充摘要（当前实测需付费，普通免费 Key 不启用）；Yahoo 作为摘要和标题线索来源。只有标题时保留审计记录，不作为正文事实输入模型。宏观与政策报道使用美联储 RSS 和正文，FRED 数值保留观察日期、单位与版本日期。社交来源均缺失时不生成情绪分数，也不把新闻情绪替代为市场共识。估值不再读取 Yahoo 无时点的 PE；只在最新期间的正值 TTM EPS 可核验时计算 PE，否则明确未知，不加总季度 EPS或推算多类别股票总市值。

财务金额保留原始精度；季度、半年、九个月及全年分开。累计 EPS 使用直接披露值，同比只使用同一申报中的比较值；归母净利润与含非控股权益利润分列。下游文本出现无法由披露值支持的累计 EPS 声明时，报告退回已核验资料并标记核验失败。历史报告不会被静默改写。

运行 npm run research:check 可检查公开数据源连通性，不读取账户或调用模型。Yahoo 对中国大陆出口存在地区限制，StockTwits 可能被 Cloudflare 拦截；重试无法解决地区限制。可配置已有授权的 TRADINGAGENTS_HTTP_PROXY，或将 TRADINGAGENTS_MARKET_VENDOR 设为 alpha_vantage 并提供 ALPHA_VANTAGE_API_KEY；复权日线需要相应 API 权限及配额。研究行情默认优先 thinkorswim，不可用或口径未核验时回退 TRADINGAGENTS_MARKET_FALLBACK（默认 yfinance）；新闻采用官方公告和 Yahoo 摘要，Alpha Vantage 仅作为具备相应接口授权时的可选来源；TRADINGAGENTS_NEWS_VENDOR 仅保留上游兼容。FRED_API_KEY 与 SEC_EDGAR_USER_AGENT 会传入隔离子进程，本机模型桥接绕过代理。

运行 npm run research:sources -- GOOG 验证实际来源和正文覆盖，保存公开资料但不调用模型、读取账户或发送飞书消息。运行 npm run research:test 执行 Python 离线数据回归。每个任务保存 source-evidence.json、data-audit.jsonl、financial-facts.json、data-coverage.json 和 account-context.json，保存脱敏来源结果、期间、单位、计算输入和覆盖状态；这些文件属于私有账户数据目录。修改代码后重新构建并重启服务生效。

研究代理地址由项目 .env 的 TRADINGAGENTS_HTTP_PROXY 提供，代码将其传给 Python 子进程。后台服务不读取终端的 .bashrc，也不需要在终端先执行 proxy_on；关闭终端的 HTTP_PROXY / HTTPS_PROXY 不影响这项独立配置。修改 .env 后需重启后台服务加载，代理服务本身须保持可达。

`UND_ERR_CONNECT_TIMEOUT` 表示服务连接模型网关超时；它与 Python 获取行情、新闻所用的研究数据代理无关。模型连接单独允许等待 30 秒（原生 fetch 默认约 10 秒），普通问答与研究共用模型连接池；完整请求仍受 `MODEL_TIMEOUT_SECONDS` 限制。研究遇到短暂连接失败时，分别等待 5 秒、15 秒再重试，重试和等待都计入本次请求时限与任务预算。`/research status` 会显示重试等待；取消或耗尽预算立即停止。持续失败会明确说明模型连接问题，可稍后重新发送原 `/research 股票代码` 命令。

## Discord 动态活动卡片

看板左下角打开“Discord 动态状态”。创建自己的 [Discord Application](https://discord.com/developers/applications)，在 General Information 中复制 Application ID，填入看板并设置入市日期。点击“刷新预览”核对内容，再开启同步并保存。本机 Discord 桌面端需要运行并已登录，Discord 的活动分享设置需要允许展示。

活动分两行展示：总仓位（含现金的账户净值）、总盈亏百分比、今日盈亏金额、昨日固定收益率。总盈亏优先使用已确认的 USD 净投入成本；未配置成本时使用以入市日期为起点的累计 TWR。入市天数不再占用活动卡片。金额缺失显示占位文字，不按零补齐。

同步每分钟重新推送当前活动，收益数据每 5 分钟读取，每 10 秒检查连接与新鲜度。息屏或锁屏时继续同步。日期回退不能覆盖较新的数据；IB 同日修订仍保存在业绩源，但不会覆盖已固定的昨日快照。第一行缩写为“净值 金额 · 总 收益率”，账户数据过期时将“净值”改为“旧值”，采集时间保留在标题和看板中。失联超过 45 秒或反复收到过期摘要会清除活动，恢复后重新读取；完全休眠时本机程序无法更新。封面跟随昨日固定收益率，可见范围由 Discord 活动分享设置控制。

服务器部署使用 `DISCORD_TRANSPORT=remote`，支持 `ACCESS_MODE=password` 和 `intranet`。`PresenceData` 在服务器汇总数据，Mac 每约 15 秒读取 `GET /api/discord/remote`，再由 `DiscordBridge` 连接本机 Discord RPC。专用 Bearer 令牌只用于读取摘要和回报状态；摘要不包含持仓明细。内网免密模式仍须经过原 HTTPS 入口，不能通过 SSH 直连后端绕过入口校验。

配置远程模式后，运行 `npm run build` 和 `node scripts/package-discord-mac.mjs`，再重启看板。安装包保存在私有 `DATA_DIR/discord-mac.tar.gz`，可在“Discord 动态状态”中下载。包内只有同步代码、依赖、专用摘要令牌和公开服务证书，不含 IB 凭据、模型密钥或证书私钥。服务证书或令牌变更后需重新打包安装。

Mac 安装 Node.js 24+，打开并登录 Discord 桌面端，然后解压同步包、双击 `Install.command`。也可在解压目录运行 `node scripts/install-discord-mac.mjs`。检查会验证服务器摘要和 Discord RPC 握手，成功后设为登录自启；最终以看板“最近成功同步”和真实个人活动卡片为准。程序使用包内公开证书验证 HTTPS，无需关闭证书校验。

`node scripts/discord-sync.mjs --check-server` 仅检查服务器；`--check` 同时检查 Discord 桌面端连接。两种检查均不发送活动。密码模式仍支持打包时传入 SSH 目标；内网免密模式不支持该方式。

服务器同步包 0.1.2 起，在连接检查通过后会停用旧的 local.ibkr-mcp-dashboard 登录启动项，保留其数据，只保留 local.ibkr-discord-sync 发布活动，避免旧本机看板与服务器同步程序交替覆盖卡片。

## 本金与本地业绩历史

Discord 设置可保存 USD 净投入成本及确认日期。“累计”按（当前 USD 账户净值 − USD 净成本）÷ USD 净成本计算，累计盈亏为净值减成本；不依赖完整历史 TWR，也不再显示累计 TWR 缺失提示。日收益仍单独使用对应交易日的 TWR。新入出金后需要更新成本。若选用换汇成本，应扣除反向换汇并核对其他资金进出，不能重复累计美元买入总额。未配置成本时仍使用历史累计 TWR。

业绩采集独立于 Discord 开关运行。`DATA_DIR/performance-history.json` 按账户、日期保存净值、前一日期和单日 TWR，原子写入、权限 0600；首次会恢复本目录已有日报中的有效数据。IB 返回较旧日期不会删除较新的本地记录，后续完整修订会更新对应日期。`pa-performance-latest.json` 保存最近一次原始响应以便核对。

“今日净值变动”使用 IB 当前净值与本地上一交易日收盘净值比较。存在当日入出金时，净值差不等于投资盈亏；上一交易日 TWR 单独展示。收益日期和来源均保留，不用缺失值覆盖已知历史。

日收益展示只选择已完成的美股交易日，排除周末和已知休市日，并以 SPY 已完成日线作为日期上限。目标交易日的数据尚未返回时，使用最近一个有收益记录的交易日并标注日期。交易日历查询失败时按本地交易日规则筛选。已有周末估值保留在原始历史中，但不会进入交易日收益展示或打断交易日收益链。

Discord 与飞书日报共用 DATA_DIR/discord-daily-snapshots.json（0600）的账户收益快照，按账户、币种和日期隔离。飞书日报的账户数据准备完成时立即封板，DC 下次同步即切换，可早于日报文字分析生成和发送，不再等待中午。缺报时仍保留北京时间次日 12:00 的兜底截止，只使用午前保存的最近记录，禁止用午后数据补写。封板后，日报重生成、IB 后续变化与服务重启都不覆盖该日数值。新日期尚未封板时，DC 继续展示最近一份已封板收益，并标注“上日”和该记录的实际日期；没有任何历史记录时才显示缺数符号。

今日以纽约 04:00–20:00 为展示时段，20:00 后切换到下一日等待盘前；休市日显示“休市”，夏冬令时自动换算。金额来自 IB 当前日期的净值差，只有基准日期正确且与当日 TWR 核对一致时才展示；有资金差异显示“待核对”，缺数显示“待数据”，超过 10 分钟显示“待更新”。今日基准使用 IB 当前返回的上一日净值，而非固定快照，避免把历史修订计入今日盈亏。

净值与今日金额分别读取账户接口和 PA 当日业绩。DC 今日金额直接使用最新共享业绩缓存，不等待交易日历或上一交易日查询。业绩请求失败、或活动时段未返回当日点时，按 30/60/120 秒重试，恢复后回到每 5 分钟读取。同日有效记录不会被缺字段响应清空，并随业绩历史持久化；旧版可从原始响应恢复，保留原读取时间。超过 10 分钟仍显示“待更新”，已知资金差异仍显示“待核对”，不会用旧金额或净值硬填。

## Linux 常驻与开机自启

构建并配置 `.env` 后运行 `npm run service:install`。安装器使用当前 Node.js 的绝对路径，写入用户 systemd 服务并启用每分钟 HTTP 健康检查。异常退出后 5 秒重启；连续三次健康检查失败时重新启动。主动停止的服务不会被健康检查拉起，日志由系统 journal 管理。

运行用户须已启用 linger，退出登录后才能继续运行。用 `loginctl show-user "$USER" -p Linger` 检查；未开启时由管理员执行 `loginctl enable-linger <用户名>`。安装器会验证此项及启动状态；`npm run service:install -- --dry-run` 可预览配置。

```bash
systemctl --user status ibkr-mcp-dashboard.service
systemctl --user list-timers ibkr-mcp-dashboard-health.timer
journalctl --user -u ibkr-mcp-dashboard.service -f
systemctl --user restart ibkr-mcp-dashboard.service
# 同时停止并取消开机启动
systemctl --user disable --now ibkr-mcp-dashboard-health.timer ibkr-mcp-dashboard.service
```

通过 SSH 私下访问时，在服务 `.env` 中设置 `ACCESS_MODE=password`、`HOST=127.0.0.1`、`PORT=8048` 和 `PUBLIC_URL=http://127.0.0.1:18048`。在自己的电脑执行 `ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:18048:127.0.0.1:8048 <SSH目标>`，保持隧道开启，然后用同一浏览器打开 `http://127.0.0.1:18048` 并完成 IB 授权。18048 是本机转发端口，8048 是服务器监听端口；采用独立的转发端口可避免误入本机运行的另一份看板。若更换转发端口，必须同步修改 PUBLIC_URL 并重启服务器。查看初始看板密码使用服务器上的 `npm run show-login`。

## 内网 HTTPS 直连

需要内网免密时，设置 ACCESS_MODE=intranet，并配置内网 HTTPS 证书。页面自动建立带 Secure Cookie 的会话，服务重启后自动恢复；不再显示看板密码及密码设置。免密仅接受内网 HTTPS 入口，保留 Host、Origin、CSRF 和 IB 授权回调校验。浏览器仍需信任服务证书，IB 官方授权独立于看板密码。

Mac 能访问服务器私有 IPv4 时，可直接使用固定内网 HTTPS 地址。IB 不接受私有 IP 的 HTTP 回调。后端保持 HOST=127.0.0.1、PORT=8048 和 ACCESS_MODE=password，将 PUBLIC_URL 设置为 https://私有IPv4:8443，并配置 INTRANET_HTTPS_CERT_FILE、INTRANET_HTTPS_KEY_FILE。证书必须包含该 IP 的 SAN、未过期且 CA:FALSE；证书与私钥放在私有 data/ 目录，权限 0600。INTRANET_CERT_PORT 默认 8080，与 HTTPS 和后端端口分别使用。

服务同时启动内网 HTTPS 转发和证书安装页，由原 systemd 服务统一管理。首次访问 http://私有IPv4:8080，下载服务证书，在 Mac“钥匙串访问”中只把该证书的 SSL 信任设为“始终信任”，然后直接打开 HTTPS 看板。HTTP 安装页仅返回公开证书及步骤，账户、登录、OAuth 回调仍通过 HTTPS。TLS 证书链、IP 匹配、密码、Secure Cookie、CSRF、回调与 SSE 已有集成测试。证书到期或 IP 变化前需更新服务证书，更新后在 Mac 重新信任。

## macOS 登录自启

构建完成并停止手动启动的服务后，运行 `npm run service:install`。安装器配置 `local.ibkr-mcp-dashboard` 登录启动项，验证健康接口后才报告成功；启动失败会停用该启动项。服务由 launchd 管理，异常退出后重启，运行日志位于 `~/Library/Logs/IBKRDashboard`。日志不能放在受 macOS 后台访问限制的 Documents 目录。登录自启不能让本地 RPC 在 Mac 关机后继续运行。

## 服务器专属离线快照

可将带日期的短摘要手动保存在 Discord 的服务器专属人称代词栏。它由 Discord 保存，在线活动关闭或 Mac 离线后仍保留，且不会更改主要个人资料。此方式不是自动更新接口，必须同时更新日期和数值；例如 `M/D·N天·USD金额·总收益率·昨收益率`。现有 Rich Presence 可在看板中单独启停。
